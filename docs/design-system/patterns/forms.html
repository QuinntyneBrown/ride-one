Pattern

Forms

Wattzup has two forms: ride setup and unlock. Both validate on submit, keep what the rider typed, and explain every error next to its field and in a summary.

WCAG 2.2 AA

Overview

Forms use form fields, number steppers, sliders, switches and mode cards, arranged by form layout. Button-triggered editing never happens inline: setup is its own screen (AGENTS.md).

When to use

  • Changing the plan before a ride: setup (/setup).
  • Entering the API key when the server requires one: unlock.
  • Never for a single value the rider nudges mid-ride — that is the level control.

Structure

  1. Heading and one-line intro.
  2. Error summary (only after a failed submit).
  3. Fields in reading order: mode, presets, values, toggles.
  4. Preview (setup) and the single submit action, with its disabled reason underneath.

States

  • Default — defaults or the saved draft; Start enabled.
  • Invalid — inline errors, summary focused, Start disabled with the reason.
  • Submitting — inputs read-only, button busy (Starting…).
  • Server error — danger alert beside the button; values kept.
  • Loading — skeleton of the same layout.

Responsive

  • Fields stack in one column below 640px; steppers sit in three columns from 640px.
  • From 1024px the setup preview is a side panel; below that it follows the form.

Accessibility

  • Every control has a visible label; errors are in aria-describedby and set aria-invalid.
  • On a failed submit focus moves to the summary; each summary link focuses its field.
  • Nothing validates while typing, so the rider is never told off mid-entry (WCAG 3.3.1, 3.3.3).
  • Unlock uses autocomplete="current-password" (WCAG 3.3.7, 3.3.8).

Content

  • Errors give the rule and the fix: "Enter 1 to 30 rounds."
  • Summary title counts: "2 things to fix before you start".
