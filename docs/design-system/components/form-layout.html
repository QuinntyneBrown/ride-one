Form layout

Form layout arranges fields into columns, puts the error summary at the top and the one submit action last.

WCAG 2.2 AAStatus: stable

Overview

.field-grid lays fields in one column on phones and three (or two with --2) from 640px. On submit with errors, an alert with .form-summary appears above the fields, lists each error as a link to its field, takes focus, and Start ride stays disabled with its reason below it.

Anatomy

  1. SummaryDanger alert with a 4px edge, focused on submit.
  2. LinksOne per error; each focuses its field.

Sizes

States

VariantReadySubmittingInvalid
Submit

Both themes

2 things to fix before you start
2 things to fix before you start
  • Submitting: every control read-only, the button busy, nothing shifts.
  • Server error: a danger alert beside the button; values kept.

Responsive behaviour

  • One column below 640px; steppers in three (or two) columns from 640px.
  • The submit button sits in the side panel from 1024px and below the form on smaller screens.

Theming

Uses alert tokens; --border-width-accent for the summary edge.

Accessibility

Role and pattern

A <form> (or the setup region) with an error summary that is role="alert" and tabindex="-1".

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the control in DOM order.
EnterOn a summary link: focuses the field.

Content

  • Summary title: "{n} things to fix before you start".
  • Hint under a disabled Start: "Fix the 2 fields marked in red to start."
