Component · Containers and overlays

Dialog

Dialogs interrupt for a decision (End this ride? Replace the ride in progress?) or show detail (Diagnostics). The page behind is inert.

WCAG 2.2 AAStatus: stable

Overview

Use a dialog only when the rider must decide before continuing, or for a read-only panel opened on request. Never for forms (AGENTS.md: button-triggered editing opens a CDK Dialog or navigates). In Angular use CDK Dialog; never hand-roll.

Anatomy

  1. IconTone: danger or info.
  2. Title and descriptionh3 + muted body; aria-labelledby/describedby.
  3. CloseGhost icon button.
  4. BodyErrors at the top.
  5. FooterSafe action, then the commit action.

Responsive behaviour

  • Below 640px the panel is a bottom sheet (--radius-xl top corners, sticky footer, safe-area padding).
  • From 640px it is centred with --radius-lg.

Theming

Panel --color-bg-surface-raised, --shadow-4; backdrop --color-bg-backdrop.

Accessibility

Role and pattern

APG Dialog (modal): role="dialog" aria-modal="true", labelled by the title, described by the description; the page behind is inert.

Keyboard

KeyAction
Tab / Shift+TabCycles inside the dialog.
EscCloses as the safe action (Keep riding).
EnterActivates the focused button.

Focus

Opens on the safe button; when every button is busy, focus sits on the dialog container. On close focus returns to the trigger.

Labelling

Close button "Close"; title is the accessible name.

Contrast

Text on raised
Muted on raised

Motion

Sheet slides up / dialog scales in over --duration-slow; none under reduced motion.

Touch

Buttons 40px; sheet keeps the footer above the home indicator.

Content

  • Title is the question; description states the consequence with numbers.
  • Buttons: safe = what continues, commit = what happens.
