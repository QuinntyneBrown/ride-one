# L1 - High-Level Requirements

These requirements were derived from the existing Python/aiohttp prototype (`echelon_server.py`) and its single-page UI (`index.html`). The target implementation is an **ASP.NET Core (.NET) backend** and an **Angular frontend**. Behaviour from the prototype is preserved unless a requirement states otherwise.

## L1-001: Bike discovery and connection
The system must automatically find the chosen nearby Echelon machine (the bike or the treadmill, L1-013) over Bluetooth Low Energy, connect to it, keep the connection alive, and recover from disconnects and errors without user intervention.

## L1-002: Telemetry decoding
The system must decode the chosen machine's notification packets into live metrics: on the bike, cadence, speed (derived from cadence) and current resistance level, from which it must estimate power and the ride's average power, distance and energy, labelled as estimates; on the treadmill, speed and incline, from which it must derive the ride's distance and the belt's state.

## L1-003: Resistance control
The system must let the rider set the bike's resistance level, or the treadmill's speed and incline, including overriding a running plan until its next segment, must report both the requested (target) value and the value the machine actually reports, and must log each command with its source and acknowledgement.

## L1-004: Interval workout engine
The system must run finite workout plans (HIIT intervals with an optional warm-up and cool-down, or one flat level, speed or incline) made of segments, setting the bike's resistance, or the treadmill's speed and incline, automatically for each segment, letting the rider pause and resume, and handling the machine disconnecting and shutting off.

## L1-005: Real-time state API
The backend must expose the full live state through an HTTP API, including a push stream that delivers every state change to connected UIs in real time, and endpoints to choose the machine and to control resistance, speed, incline and workouts.

## L1-006: Live metrics dashboard
The frontend must show the rider the connection status; on the bike, live estimated power against the plan's target, cadence, speed and resistance; on the treadmill, speed, incline, distance and pace; the ride's totals, the commands sent to the machine, notifications about the connection and commands, and controls for changing resistance, or speed and incline.

## L1-007: Workout visualisation and cues
The frontend must show the active workout as a countdown of the current segment with its phase, the ride's elapsed and total time, on the bike a trace of power against the plan, on the treadmill the countdown to the belt starting, and visual and optional audio cues at segment changes and in the final seconds of each segment. It must also let the rider choose the machine and set up, start, pause, resume, end and replace workouts.

## L1-008: Diagnostics and observability
The system must record raw Bluetooth packets, keep a persisted snapshot of the latest state, track how long live data has been on screen, produce structured logs, and show a diagnostics view for troubleshooting.

## L1-009: Security
The system must protect the bike-control API from unauthorised use, validate all input, and avoid exposing the service beyond what the deployment needs.

## L1-010: Performance and reliability
The system must deliver live data to the screen with low latency, use resources efficiently over long rides, and keep running through bike, Bluetooth and browser-connection failures.

## L1-011: Responsive and accessible UI
The frontend must work on every viewport size from phone to large desktop, and must be usable with a keyboard, screen readers and reduced-motion settings.

## L1-012: Platform and technology
The backend must be built on .NET and the frontend on Angular, with the Bluetooth layer isolated behind an abstraction so the system can run on Windows, Linux and macOS.

## L1-013: Treadmill support
The system must support an Echelon treadmill as a second machine, one machine at a time: the rider chooses the bike or the treadmill, and the system finds and connects to that machine, decodes its speed and incline and derives the distance, controls its speed and incline, starts the belt only after a visible and announced countdown and stops it whenever the ride pauses, ends or is stopped, and runs the same kinds of plans on it with speeds and inclines in place of resistance levels.
