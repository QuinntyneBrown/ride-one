# L2 - Detailed Requirements

This document is rewritten for Telo Ride 1 and drops what Telo Ride 1 leaves out (see `L1.md`).
A requirement kept from Telo Ride keeps its ID, so the IDs have gaps; new requirements start at
L2-167, and a removed ID is never used again. Riding in Ibiza (L2-173 to L2-177) is new to
Telo Ride 1 and takes new IDs, though Telo Ride's courses were its starting point.

Each L2 traces to one L1 in `L1.md`. Every acceptance test names the L2s it covers in a header
comment:

```typescript
// Acceptance Test
// Traces to: L2-011, L2-013
// Description: Pair an Echelon EX-5s from Connect Bike and land on The Class
```

The mocks (`docs/mocks/`) are the source of truth for layout and copy; quoted strings are
verbatim from them, except where the class changed after they were drawn: the class's name, its
times, its plan and riding in Ibiza are ahead of the mocks (see *Mock gaps*). The criteria reuse
the mocks' cast, with the class's own numbers:

- **The rider:** one person on their own bike at home, at one of two stages:
  - **new rider:** has never paired a bike; no rides.
  - **returning rider:** 6 rides of the class, best output 342 kJ, last output 318 kJ.
- **The bike:** an Echelon EX-5s, identifier `EX5S-0bf669f1`, strong signal.
- **The class:** Intervals to the Beat (L2-080).
- **The course:** Ibiza Sunset Strip (L2-174).
- **Mid-ride moment:** 5:30 of 20:00, in the second recovery with 0:30 left; 229 W against a 231 W
  target, 91 rpm aiming 90, resistance 13 of 32.
- **Finished rides:** a new best of 351 kJ at 293 W average, its 17 efforts between 251 and
  452 W with the last the strongest; and a ride short of the best at 318 kJ, 265 W average.

The cast's numbers are examples, not rules: an output, a best or a percentage is whatever the
rules below compute.

Terms are used in one sense only:

- **Resistance:** the level the bike reports.
- **Target resistance:** the level the app asks for.
- **Plan:** the timed segments the class follows. A **segment** has a kind (warm-up, work,
  recover, cool-down), a duration, a level and a cadence aim.
- **Effort:** one of the plan's 17 work segments.
- **Ride:** one run of the class. A ride is **finished** when its clock reaches the plan's
  length.
- **Output:** the work the rider did in a ride, in kJ.
- **Record:** the rider's ride count, best output and last output, kept on the device.
- **Course:** Ibiza Sunset Strip, the one road the rider can ride the class on in place of its
  video. **In Ibiza** means a ride drawn on the course; **with the class video** means the other.
- **Music:** the one background track, *Beautiful Boom Bap* (L2-176).
- **Blocked:** the browser cannot reach a bike, because it has no Web Bluetooth (L2-008) or the
  page is not secure (L2-009).

The screens are at `/connect` (Connect Bike), `/` (The Class), `/ride` (Class Ride) and `/done`
(Class Done).

Breakpoints are named as in the design system: **phone** < 640 px, **sm** ≥ 640 px,
**md** ≥ 768 px, **lg** ≥ 1024 px, **xl** ≥ 1280 px.

## L2-007: Supported bikes list
**Traces to:** L1-002

**Acceptance Criteria:**
1. Given Connect Bike, when it opens in any state, then a "Works with" section lists, in order: "Echelon EX-5s", "Echelon EX-3", "Echelon EX-8s" and "Echelon Connect Sport", each "Full control", and "Other FTMS smart bikes", "Beta".
2. Given an Echelon bike, when it is connected, then the app reads its telemetry and sets its resistance (full control, L2-013).
3. Given a bike that advertises FTMS (service `0x1826`) and is not an Echelon, when it is connected, then the app reads Indoor Bike Data and, if the bike grants control, sets its resistance (L2-014).
4. Given a viewport at sm or wider, when the list shows, then it is two columns; on a phone it is one.

## L2-008: Browser support
**Traces to:** L1-002

Web Bluetooth exists only in Chromium browsers (Chrome and Edge on Windows, macOS, Linux,
ChromeOS and Android).

**Acceptance Criteria:**
1. Given a browser without `navigator.bluetooth` on a secure page, when Connect Bike opens, then the device card is replaced by an alert (`role="alert"`). It reads "This browser can't reach the bike" and "Open Telo Ride 1 in Chrome or Edge on a laptop or Android tablet. Safari and Firefox don't support Web Bluetooth yet.", with "Try again".
2. Given such a browser, when The Class opens, then an alert (`role="alert"`) under the header reads "Open Telo Ride 1 in Chrome or Edge." with "Bluetooth to the bike only works there — you can look around, but not ride." and **Copy link**. The class, its video and the rider's record stay readable.
3. Given such a browser, when the rider presses **Copy link**, then the page address is copied to the clipboard and the button shows its copied state.
4. Given a supported browser on a secure page, when any screen opens, then no unsupported-browser message is shown.

## L2-009: Secure context
**Traces to:** L1-002

Browsers allow Web Bluetooth only on HTTPS pages (and `localhost`). On a plain `http` page a
Chromium browser has no `navigator.bluetooth` either, so an insecure page is told to go secure,
never to change browser.

**Acceptance Criteria:**
1. Given a page served over plain `http` other than `localhost`, when The Class opens, then an alert (`role="alert"`) under the header reads "Open the secure version of this page." with "Bluetooth is blocked on plain http, so the bike can’t connect." and **Open over HTTPS**. The link goes to the same path on `https://`.
2. Given a production deployment, when a request arrives over `http`, then it is redirected to `https` and responses carry `Strict-Transport-Security`.
3. Given a secure context, when any screen opens, then no HTTPS notice is shown.
4. Given a page served over plain `http` other than `localhost`, when Connect Bike opens, then the device card is replaced by an alert (`role="alert"`). It reads "Open the secure version of this page" and "Bluetooth is blocked on plain http, so the bike can’t connect.", with **Open over HTTPS**, which goes to the same path on `https://`.

## L2-010: Blocked rides
**Traces to:** L1-002

When the browser is blocked, the app says why and does not start a ride.

**Acceptance Criteria:**
1. Given a blocked browser, when The Class opens, then the header reads "No bike · Connect", and the start button reads "Connect your bike", is disabled, and is followed by "The class needs the bike to set resistance.".
2. Given a blocked browser, when the `/ride` address is opened, then The Class opens instead and nothing is requested from Bluetooth.
3. Given a blocked browser, when the rider uses The Class or the page-not-found screen, then the video, the plan chart and the record work normally.

## L2-011: Connect Bike
**Traces to:** L1-003

Connect Bike (`/connect`) is where the bike is paired. A new rider starts here, and any rider
reaches it from The Class's header.

**Acceptance Criteria:**
1. Given Connect Bike, when it opens, then it shows the wordmark, Full screen, the bike photo, "Connect your bike" and "Pedal once to wake it up. Telo Ride 1 reads your power and sets resistance for every hill and interval.", and no navigation.
2. Given the rider starts a search, when no bike has been picked yet, then the card shows a spinner with "Looking for bikes nearby…" (`role="status"`) and a disabled "Searching…" button.
3. Given Connect Bike at rest, when no bike has been picked, then the card names the offered model, "Echelon EX-5s", with no identifier, and the button reads "Pair Echelon EX-5s". Given the rider has picked a bike, when the card shows it, then it gives its name ("Echelon EX-5s") and identifier ("EX5S-0bf669f1") as text; a bike with no identifier shows its name alone. No signal strength is shown (open question 17).
4. Given the rider has picked a bike, when pairing runs, then the button is disabled with `aria-busy="true"`, a spinner and "Pairing…". Pairing starts with the pick; the rider does not press the button a second time.
5. Given pairing succeeds, when the bike is connected, then the card shows a check (`aria-label="Paired"`) and a disabled "Paired" button. About half a second later, The Class opens with the bike connected.
6. Given a viewport at lg or wider, when Connect Bike shows, then it is two columns with the photo on the left. Below lg, the photo follows the content at up to 28 rem, square.

## L2-012: Choosing the bike
**Traces to:** L1-003

A web page cannot scan in the background. The rider picks the bike once in the browser's own
chooser, which needs a tap or click.

**Acceptance Criteria:**
1. Given Connect Bike, when the rider presses the search or pair action, then `navigator.bluetooth.requestDevice` is called with filters for the Echelon service (`0bf669f1-45f2-11e7-9598-0800200c9a66`) and FTMS (`0x1826`), and no other service is requested.
2. Given no user gesture, when the app would open the chooser, then it does not; nothing is requested from Bluetooth until the rider acts.
3. Given the rider cancels the chooser, when it closes, then Connect Bike returns to its default state with no error.
4. Given the chooser cannot open (a policy blocks it), when the request fails, then an alert (`role="alert"`) replaces the device card. It reads "Bluetooth is blocked for this page" and "Allow Bluetooth for this site in your browser’s settings, then try again." (any other failure reads "The bike list didn’t open" and "Something went wrong opening your browser’s list of bikes. Try again."), with "Try again", which opens the chooser again.

## L2-013: Echelon connection and initialisation
**Traces to:** L1-003

Bytes and UUIDs are in `docs/protocol/echelon-ble-frames.md`.

**Acceptance Criteria:**
1. Given an Echelon bike is chosen, when the app connects, then it opens GATT, gets service `0bf669f1-…`, and subscribes to the notify characteristic `0bf669f4-…` before writing anything.
2. Given the subscription is in place, when initialisation runs, then it writes `F0 A1 00 91`, `F0 A3 00 93` and `F0 B0 01 01 A2`, in that order. Each goes to `0bf669f2-…` with response, at least 300 ms after the previous one.
3. Given any write to the bike, when another is pending, then the new one waits. Writes go one at a time in the order requested.
4. Given initialisation completes, when the first notification arrives, then the bike state is `connected`. Its name is the model's name when the device name is an Echelon's (`ECH-EX5S-141844` is "Echelon EX-5s", identified as `EX5S-141844`), otherwise the device name, or the device's identifier if it has none.

## L2-014: FTMS connection and control
**Traces to:** L1-003

Other smart bikes are supported in beta through the Bluetooth SIG Fitness Machine Service.

**Acceptance Criteria:**
1. Given an FTMS bike is chosen, when the app connects, then it subscribes to Indoor Bike Data (`0x2AD2`) and to Fitness Machine Control Point (`0x2AD9`) indications, and reads Supported Resistance Level Range (`0x2AD6`).
2. Given the control point is subscribed, when the app needs to set resistance, then it first writes Request Control (op code `0x00`). Only on a Success response (`0x80 0x00 0x01`) does it send Set Target Resistance Level (op code `0x04`).
3. Given the bike refuses control or has no control point, when a ride runs, then telemetry, the clock and the video still work, no resistance command is sent, the resistance controls are disabled, and Class Ride says the rider must set the resistance by hand. _(Mock gap: this notice.)_
4. Given the bike's supported range, when the app maps levels 1 to 32 onto it, then level 1 is the minimum, level 32 the maximum, and levels in between are spaced linearly and rounded to the bike's increment.

## L2-015: The remembered bike
**Traces to:** L1-003

**Acceptance Criteria:**
1. Given a bike was paired in this browser, when Telo Ride 1 opens, then it opens on The Class without Connect Bike (L2-167). Where `navigator.bluetooth.getDevices()` exists, it reconnects to that bike without the chooser as soon as the bike advertises.
2. Given the remembered bike does not advertise, or `getDevices()` is not available, when The Class shows, then the bike is shown as not connected and the start button reads "Connect your bike" (L2-084 AC6).
3. Given the rider pairs a different bike on Connect Bike, when pairing succeeds, then that bike replaces the remembered one.
4. Given the remembered bike, when it is kept, then only its name and the browser's identifier for it are stored, on the device.

## L2-016: Keepalive
**Traces to:** L1-003

**Acceptance Criteria:**
1. Given an Echelon bike is connected and initialised, when 5 seconds pass, then between 4 and 6 keepalive frames `F0 A0 01 01 92` have been written, each with response.
2. Given the tab is hidden, when 60 seconds pass, then keepalives keep going at about one a second, timed from the clock rather than counted ticks (L2-133).
3. Given the bike disconnects, when it is gone, then keepalives stop until it reconnects.

## L2-017: Disconnect and recovery
**Traces to:** L1-003

**Acceptance Criteria:**
1. Given the bike is connected, when it disconnects (`gattserverdisconnected`) or any Web Bluetooth call fails, then the bike state becomes `disconnected`. The app retries the same bike every 3 seconds without the chooser until it connects or the rider leaves the ride.
2. Given the bike is switched off for an hour, when it is switched on and pedalled, then the app reconnects within one retry without a reload.
3. Given the rider presses **Reconnect**, when the bike is not connected, then the pending retry is cancelled and an attempt starts at once.
4. Given a reconnect succeeds during a ride, when the bike is back, then the current target resistance is sent again before anything else.
5. Given a Web Bluetooth error, when it is recorded, then its name and message go to the console as text (L2-115), and the rider sees only the app's own message.

2. Given Bluetooth is off, when the alert is shown, then it never says that no bike was found.
3. Given the rider presses "Try again", when Bluetooth is now on, then Connect Bike returns to its default state.

## L2-020: Echelon telemetry decoding
**Traces to:** L1-004

**Acceptance Criteria:**
1. Given a notification `F0 D2 01 0C CF`, when it is decoded, then resistance is 12.
2. Given a notification `F0 D1 09 00 05 00 00 00 00 00 50 00 1F`, when it is decoded, then cadence is 80 rpm.
3. Given a frame shorter than 4 bytes, with byte 0 other than `F0`, of an unknown type, or a `D1` shorter than 13 bytes, when it arrives, then it is ignored without an error.
4. Given a `D0` frame, when it arrives, then it is ignored without an error.
5. Given no `D1` frame for 5 seconds while connected, when the readouts show, then cadence and power show "—" rather than their last values.

---

## L2-021: FTMS telemetry decoding
**Traces to:** L1-004

**Acceptance Criteria:**
1. Given an Indoor Bike Data notification, when it is decoded, then its flags decide which fields are present. Cadence is uint16 in 0.5 rpm and power sint16 in W; every other field is skipped by its length.
2. Given the bike reports power, when power is shown, then it is the reported value, not an estimate.
3. Given a field the flags say is absent, when the readouts show, then that metric falls back to its estimate (L2-023) or "—".
4. Given a notification shorter than its flags require, when it arrives, then it is ignored without an error.

---

## L2-023: Power and output
**Traces to:** L1-004

The Echelon reports no power, so the app estimates it.

**Acceptance Criteria:**
1. Given an Echelon with cadence 95 and resistance 18, when power is estimated, then it is max(0, round(95 × (0.55 + 18 × 0.155))) = 317 W.
2. Given cadence or resistance is unknown, when power is estimated, then it is unknown and shown as "—".
3. Given a segment with cadence aim 72 and level 6, when target power is computed, then it is 107 W by the same formula; with aim 90 and level 13 it is 231 W, and with aim 110 and level 22 it is 436 W.
4. Given each running second, when output is updated, then the second's power ÷ 1000 is added to the ride's output in kJ; a second with unknown power adds nothing.
5. Given a paused ride, when time passes, then output does not grow.

## L2-024: Simulated bike
**Traces to:** L1-004

**Acceptance Criteria:**
1. Given a development build opened with `?simulate`, when the rider connects, then a simulated Echelon EX-5s connects without the chooser and sends `D1` and `D2` frames once a second.

4. Given every feature, when it is exercised end to end, then it can run against the simulated bike.

## L2-025: Set resistance command
**Traces to:** L1-005

**Acceptance Criteria:**
1. Given an Echelon and a target resistance of 12, when it is sent, then the bytes `F0 B1 01 0C AE` are written with response. For 32, the bytes are `F0 B1 01 20 C2`.
2. Given a target outside 1 to 32, when it is requested, then it is clamped to that range before it is sent.
3. Given an FTMS bike with control, when a target is sent, then it goes as Set Target Resistance Level, mapped by L2-014 AC4.

## L2-026: Target resistance and resistance
**Traces to:** L1-005

**Acceptance Criteria:**
1. Given a target resistance was sent, when the bike reports a different resistance, then the readout shows the bike's resistance ("13" and "of 32", `aria-label="Resistance 13 of 32"`), and the target stays the requested level.
2. Given the bike reports a new resistance, when the readout updates, then it shows the new value within one second.
3. Given no resistance has been reported, when the readout shows, then it reads "—".

## L2-027: Plan-driven resistance
**Traces to:** L1-005

**Acceptance Criteria:**
1. Given a class ride starts, when its clock starts, then the first segment's level is sent as the target resistance.
2. Given a running ride, when a segment starts, then its level is sent as the target resistance within 500 ms of the segment boundary.
3. Given a paused ride, when time passes, then no segment changes and no plan command is sent.
4. Given the bike reconnects mid-segment, when it is back, then the current segment's level is sent again.

---

## L2-028: Manual resistance
**Traces to:** L1-005

**Acceptance Criteria:**
1. Given a class ride with a connected bike, when the rider presses "Raise resistance" or "Lower resistance", then the target resistance moves by one level, clamped to 1 to 32, and is sent.
2. Given the rider changes the level by hand during a segment, when the next segment starts, then the plan's level applies again.
3. Given the bike is lost, when the resistance controls show, then both buttons are disabled.
4. Given a paused ride with a connected bike, when the resistance controls show, then they stay enabled.

## L2-087: Class Ride
**Traces to:** L1-015

Class Ride is at `/ride`.

**Acceptance Criteria:**

6. Given the rider leaves or finishes, when Class Ride closes, then the music stops and its audio element and buffers are released. No music plays on The Class, Connect Bike or Class Done.
7. Given the music cannot be loaded or the browser refuses to play it, when the ride runs, then the ride and the course carry on without it, the "Music" button is disabled, and no alert interrupts the rider.
8. Given the tab is hidden during a ride in Ibiza, when the ride clock runs on (L2-133), then the music plays on with it.
9. Given the app, when it runs, then this is the only music it has: no other track, no way to choose one, and no synthesised ride sound.

## L2-177: The course on a low-power tablet
**Traces to:** L1-022

**Acceptance Criteria:**
1. Given any place on the course, when a frame is drawn, then it sends the GPU no more than 120,000 triangles in no more than 140 draw calls, with no shadow map and no texture on the map.
2. Given the course's model, when it is served, then it is no more than 3 MB gzipped, and the music no more than 4 MB.
3. Given a ride in Ibiza opens, when the course is first drawn, then it is drawn at 1 device pixel a CSS pixel with no bloom. Given 90 frames that average within 1.1 of the display's frame period, then it steps up through 1.5, 1.5 with bloom and 2 with bloom; given 90 frames that average over 1.6 of it, then it steps down (to 0.75 at the least) and steps up no more.
4. Given a ride in Ibiza on the reference tablet, when it runs, then the readouts stay within L2-134 and no frame of the interface takes longer than 100 ms (L2-136 AC3).
5. Given a full 20:00 ride in Ibiza, when the page's memory is measured, then it grows by at most 50 MB from the first minute to the last (L2-138 AC1).

## Open questions

Each of these is a place where the design, `AGENTS.md` and these requirements disagree, or where
a rule is proposed here because the design gives only a placeholder.

1. **Where the class comes from.** Closed by ADR 0037: Telo Ride 1 has no backend, and the one
   class, with its plan, ships with the app. L2-080 AC5 is met by the app's own files, and
   L2-131 needs no connection but the app's origin and YouTube.
2. **On target (L2-170).** The prototype shows a fixed 84 %. The rule here (within 10 % of target
   power) is a proposal. Every segment of Intervals to the Beat has a cadence aim, so it now
   counts the warm-up and the cool-down too.
3. **Time (L2-078 AC2).** The design shows a time 12 seconds past its plan's length. A ride
   finishes when the clock reaches 20:00, so Time reads 20:00 for every finished ride; whether it
   stays on the screen is open.
4. **Output.** The prototype computes output as 0.19 × seconds. L2-023 sums the rider's power.
5. **"Open Telo Ride in Chrome or Edge."** Closed by slice 28.7: the design's copy omitted the
   "1". L2-172 AC2 stands, so the mock and L2-008 AC2 now read "Open Telo Ride 1 in Chrome or
   Edge."
6. **HTTPS on Connect Bike (L2-009 AC4).** Closed by slice 29.2. The design sends a rider on
   plain http to the change-your-browser alert. These requirements keep a separate HTTPS alert
   there, and the mock `connect-bike/needs-https` now draws it: the alert of the other states with
   a lock and **Open over HTTPS** as a primary link.
7. **Routes.** `/connect`, `/`, `/ride` and `/done` are assumptions the mocks share.
8. **Starting without a network.** L2-135 covers a ride that loses the network. Whether the app
   must also open and start a ride with no network at all (an installed, cached app) is not
   decided; the video cannot play there either way.
9. **Light theme.** The design is dark only; L2-143 keeps the design system's light theme.
10. **Header buttons mid-ride.** The design draws Class Ride's header buttons below 44 px;
    L2-140 asks for 44.

11. **The class's words.** Closed by slice 30.1 for the class itself. Nobody had written words for
    Intervals to the Beat, so the ones proposed here from the plan stand as they are: the focus
    "Intervals" and the summary "Seventeen efforts from 15 seconds to 1:15, ridden to the beat,
    with five fast sprints to finish." (L2-080 AC1). The warm-up's cadence aim is 80 rpm and the
    cool-down's 81 rpm, as the course's file has them (`tools/blender/courses/ibiza.json`), which
    L2-080 AC2 already matched. The line under "What the bike will do" (L2-084 AC2) is closed by
    slice 30.3, which built it in L2's words: "17 efforts · 0:15 to 1:15. Resistance changes on
    its own; you just pedal.", the count and the shortest and longest effort read from the plan.
    Slice 30.2 built "Ride with" in L2-173's words
    as they stand ("Class video", "Ibiza Sunset Strip", "8.4 km · 159 m of climbing", "This browser
    can’t draw Ibiza."); the words of L2-175 and L2-176 are proposals until riding in Ibiza builds
    them.
12. **Music with the class video (L2-176 AC3).** The music plays in Ibiza only, because the class
    video has its own sound and two tracks at once fight. If it must also play under the video,
    L2-176 AC3 changes and the video is muted or ducked.
13. **How hard the class is.** By L2-023's formula the plan averages 254 W with sprints at 436 W:
    304 kJ ridden exactly on target. The levels were chosen to shape Ibiza's hills, not for a
    rider at home, and may need scaling down; the course's gradients would be rebuilt with them.
14. **Ibiza and reduced motion (L2-142 AC3).** A course is motion by nature. Whether a rider who
    asks for reduced motion is offered Ibiza, offered it with a steadier camera, or kept to the
    class video is not decided.
15. **Frame rate on a real tablet (L2-177).** The triangle, draw-call and file budgets stand in for
    a frame rate that has never been timed on a real tablet
    (`docs/screenshots/courses/README.md`).
16. **Graphics the course needs (L2-173 AC6).** "No WebGPU and no WebGL 2" is the assumed test for
    a browser that cannot draw the course.
17. **Signal strength and the bike before the pick (L2-011 AC3).** Closed by slice 29.1. The design
    drew "Strong signal · EX5S-0bf669f1" on the card before the rider pressed Pair. A page learns
    of a bike only when the rider picks it in the browser's chooser, and `requestDevice` reports
    no signal strength for it. So the card at rest names the offered model alone, the identifier
    shows from pairing onward, no signal strength is shown, and the pick itself starts pairing:
    one press, not two. The mocks `default`, `pairing` and `paired` were brought in line.
18. **How steep a level is (L2-174 AC3).** The criterion says a stretch climbs 1 % for each level
    above the plan's mean. The course as built climbs 0.855 % a level, with ramps into and out of
    each effort (`tools/blender/themes.py`, Ibiza's `grade`); `tools/blender/README.md` says so.
    Slice 30.1 found the difference and changed neither: the plan, its seconds and its levels
    agree between L2-080, the app and the course's file. Either AC3 takes the built value or the
    course is rebuilt, before riding in Ibiza is built.
19. **A file that is not there (L2-149 AC1).** Closed by slice 28.8 (ADR 0043). "Every address
    that matches no file serves the app" is read as every address a route could have. An address
    under an asset folder (`/courses/`, `/draco/`, `/fonts/`, `/icons/`, `/machines/`, `/maps/`,
    `/music/`) or ending in a file extension the build uses is 404 when no file matches: answered
    with the app, a missing script or font would be kept by the service worker as HTML. No screen's
    address has an extension or sits under those folders. The redirect and HSTS of L2-009 AC2 are
    the static host's and its configuration's (`docs/deployment.md`); the header is proved in the
    build, the redirect by a person on the host.
20. **How the two ways to ride are ridden today (L2-173 AC5).** Slice 30.2 built the choice and
    wired it to the two rides the app already had. "Class video" opens the class ride at once with
    the video alone, as L2-088 says. "Ibiza Sunset Strip" opens the carried-over ride in the
    course: World loading, then the course with the class video in its corner and the course's own
    deep house track when the video cannot play. That is not L2-174 to L2-177 (no loading screen,
    no video player, *Beautiful Boom Bap*), which journey 37 of `docs/journeys.md` builds. A browser
    that cannot draw the course never opens World loading (L2-173 AC6), so World loading's start as
    a panorama for such a browser is gone.
21. **The course's still (L2-173 AC3).** The still The Class shows is the course's one picture in
    the app (`maps/ibiza-sunset-strip-photo.jpg`), taken when Ibiza Sunset Strip was raced: it
    shows other riders, and L2-174 AC6 has the rider alone. A still of the solo ride replaces it
    when riding in Ibiza is built (slice 37.1).
22. **Where the choice is kept (L2-173 AC2).** "Kept with the record": the record does not exist
    until slice 32.1, so the choice is one value of its own in the browser's storage
    (`telo-ride.ride-with`), beside the remembered bike. Clearing the site's data forgets it
    (L2-132 AC4). Slice 32.1 decides whether it moves into the record.

## Carried-over code

The repository still holds Telo Ride's code, tests, journeys, detailed designs and ADRs for the
features these requirements leave out. The backend was removed by slice 28.8 (ADR 0043). They are no longer specified here. Each
is removed in a change of its own (`AGENTS.md`, *Carried over from Telo Ride*); until then,
nothing is added to them.

Riding in Ibiza keeps part of what was carried over: the Ibiza Sunset Strip course
(`tools/blender/courses/ibiza.json`, `courses/ibiza.glb`), the course renderer in the `world`
library and the Blender build for that one course (ADR 0034). Telo Ride's other seven courses
were removed by slice 30.1 (ADR 0042). Its world scenes, each world's own music (Ibiza's deep
house track included, which *Beautiful Boom Bap* replaces), races, bots and ghosts stay left out. The detailed design
(`docs/detailed-designs/race/ride-a-course/`) still describes a course in a race and is rewritten
for a solo class ride before L2-174 is built.
